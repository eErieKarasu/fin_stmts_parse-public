# 利润表和现金流量表勾稽校验规则

本文档梳理当前代码中利润表和现金流量表的勾稽校验规则，包括校验公式、触发条件、缺失值处理、失败归因和当前未覆盖范围。

规则实现主要位于：

- `apps/fin_stmts_parse/src/financial_inspector.py`
- `apps/fin_stmts_parse/src/core/inspect.py`
- `apps/fin_stmts_parse_mcp/service.py`

## 一、整体校验口径

### 1. 校验范围

- 利润表和现金流量表均为表内校验。
- 合并报表与单体报表在完成标准科目映射后，共用同一套校验公式。
- 当前没有根据 `is_consolidated` 对公式进行分支处理。
- 当前没有执行利润表、现金流量表与资产负债表之间的跨表校验。

### 2. 校验期间

利润表和现金流量表只取列表中的最后一个值参与校验，即：

```text
current_value = value[-1]
```

因此：

- 单值数组校验该唯一值。
- 双期间数组只校验当前期或最后一期。
- 上年同期、上期等比较期数据当前不执行勾稽校验。
- MCP 对外输出中的期间统一为 `end`。

### 3. 金额容差

所有等式使用绝对差进行判断：

```text
abs(披露值 - 复算值) <= 0.01
```

满足上述条件即判定为通过。

### 4. 通用结果状态

| 场景 | 核心结果 | 处理方式 |
|---|---|---|
| 合计存在，且存在可参与组成项，等式成立 | `pass` | 输出校验通过 |
| 合计存在，且存在可参与组成项，等式不成立 | `fail` | 输出复算值并进入失败归因 |
| 合计缺失，但存在可参与组成项 | `fail` | 按组成项计算推测合计，并供后续上层规则使用 |
| 合计缺失，且没有可参与组成项 | `fail` | 标记合计项缺失、无法推导 |
| 合计存在，但没有可参与组成项 | `skip` | 标记组成项不足、无法校验 |

整张表只要存在一条 `fail`，整体校验结果即为不通过；`skip` 本身不会导致整体失败。

### 5. 缺失值差异

利润表和现金流量表对空字符串的处理不同：

| 输入状态 | 利润表 | 现金流量表 |
|---|---|---|
| 数值或可转换为数字的字符串 | 参与计算 | 参与计算 |
| `None` | 不参与 | 不参与 |
| 非数值字符串 | 不参与 | 不参与 |
| `""` | 不参与 | 按 `0` 参与 |
| 上游规则推导出的合计 | 可参与后续规则 | 可参与后续规则 |

基础规则按实际取得的组成项计算。某个组成项缺失时，该项会被排除，而不是强制判定公式无法执行，也不会统一按零处理。

## 二、利润表校验规则

利润表包含 4 条固定执行规则和 1 条条件执行规则。完整数据下共执行 5 条校验。

### 1. 营业利润

目标科目：

```text
L04010000 营业利润
```

基础公式：

```text
营业利润
= 营业总收入
- 营业成本
- 税金及附加
- 销售费用
- 管理费用
- 研发费用
- 财务费用
+ 其他收益
+ 投资收益
+ 净敞口套期收益
+ 公允价值变动收益
+ 信用减值损失
+ 资产减值损失
+ 资产处置收益
```

参与科目：

| 符号 | 科目编码 | 科目名称 |
|---|---|---|
| `+` | `L00000000` | 营业总收入 |
| `-` | `L02010100` | 营业成本 |
| `-` | `L02010800` | 税金及附加 |
| `-` | `L02010900` | 销售费用 |
| `-` | `L03040000` | 管理费用 |
| `-` | `L02011000` | 研发费用 |
| `-` | `L03050000` | 财务费用 |
| `+` | `L02011100` | 其他收益 |
| `+` | `L04020000` | 投资收益 |
| `+` | `SY1000006` | 净敞口套期收益 |
| `+` | `L02011200` | 公允价值变动收益 |
| `+` | `SY1000016` | 信用减值损失 |
| `+` | `SG5020000` | 资产减值损失 |
| `+` | `L02011300` | 资产处置收益 |

信用减值损失、资产减值损失等项目按映射后的带符号金额直接参与计算。校验器不会自动改变正负号；若原表以负数表示损失，则以上加法符合当前设计。

### 2. 利润总额

目标科目：

```text
L05010000 利润总额
```

基础公式：

```text
利润总额
= 营业利润
+ 营业外收入
- 营业外支出
```

参与科目：

| 符号 | 科目编码 | 科目名称 |
|---|---|---|
| `+` | `L04010000` | 营业利润 |
| `+` | `L04050000` | 营业外收入 |
| `-` | `L04070000` | 营业外支出 |

如果营业利润缺失，但已由上一条规则推导出营业利润，则推导值可以继续参与利润总额校验。

### 3. 净利润与所得税费用

目标科目：

```text
L06010000 净利润
```

公式：

```text
净利润 = 利润总额 - 所得税费用
```

参与科目：

| 符号 | 科目编码 | 科目名称 |
|---|---|---|
| `+` | `L05010000` | 利润总额 |
| `-` | `L04010100` | 所得税费用 |

### 4. 净利润经营构成

目标科目：

```text
L06010000 净利润
```

公式：

```text
净利润 = 持续经营净利润 + 终止经营净利润
```

参与科目：

| 符号 | 科目编码 | 科目名称 |
|---|---|---|
| `+` | `L05010200` | 持续经营净利润 |
| `+` | `L05010300` | 终止经营净利润 |

触发条件：持续经营净利润或终止经营净利润至少有一个存在且可转换为数值。

如果两项均未提取，则整条规则不执行，不产生 `skip` 明细，也不计入校验总数。

### 5. 综合收益总额

目标科目：

```text
L07000000 综合收益总额
```

公式：

```text
综合收益总额 = 净利润 + 其他综合收益的税后净额
```

参与科目：

| 符号 | 科目编码 | 科目名称 |
|---|---|---|
| `+` | `L06010000` | 净利润 |
| `+` | `L06010100` | 其他综合收益的税后净额 |

如果净利润缺失，但已经由前面的净利润规则推导出数值，则推导值可以继续参与综合收益总额校验。

## 三、利润表新旧准则语义复核

首层校验以 `view_data` 为准。首层出现以下情况时，可以进一步使用 `canonical_data` 中的规范语义数据复核：

- 首层公式校验失败。
- 合计项缺失。
- 展示口径下没有足够组成项。
- 需要使用旧准则公式或嵌套公式推导中间合计。

### 1. 主营业务利润

```text
主营业务利润
= 营业总收入
- 营业成本
- 税金及附加
```

### 2. 营业利润变体

旧准则公式：

```text
营业利润
= 主营业务利润
+ 其他业务利润
- 销售费用
- 管理费用
- 财务费用
```

新准则公式沿用前文营业利润基础公式。

### 3. 利润总额变体

旧准则公式：

```text
利润总额
= 营业利润
+ 投资收益
+ 补贴收入
+ 营业外收入
- 营业外支出
```

新准则公式：

```text
利润总额
= 营业利润
+ 营业外收入
- 营业外支出
```

### 4. 净利润变体

支持以下三种语义公式：

```text
净利润 = 利润总额 - 所得税费用 - 少数股东损益
净利润 = 利润总额 - 所得税费用
净利润 = 持续经营净利润 + 终止经营净利润
```

### 5. 语义公式选择

每个候选语义公式只有在组成项全部能够从 canonical 数据、已推导值或嵌套语义公式中取得时，才会成为有效候选。

多个候选同时有效时：

1. 优先选择复算值与已披露合计匹配的候选。
2. 若匹配情况相同，优先选择参与科目更多的候选。

若合计已披露且语义复算通过，可将首层展示公式的失败修正为通过；若合计缺失，即使语义公式能够推导出金额，合计项本身仍标记为失败和字段缺失。

## 四、利润表失败归因

### 1. Canonical 单字段替换定位

首层公式失败时，会逐项比较 view 值与 canonical 值：

- 如果仅替换合计项为 canonical 值后等式成立，则合计项为疑似错误字段。
- 如果仅替换某一个组成项为 canonical 值后等式成立，则该组成项为疑似错误字段。
- 只有唯一候选能够使等式成立时，才会进行单字段定位。

### 2. 营业总成本辅助复核

营业利润校验失败时，如果能够取得：

```text
L02000000 营业总成本
```

则额外校验：

```text
营业总成本
= 营业成本
+ 税金及附加
+ 销售费用
+ 管理费用
+ 研发费用
+ 财务费用
```

若营业总成本披露值与明细和不一致，但使用营业总成本披露值计算营业利润能够通过，则：

- 营业利润披露值本身不作为主要嫌疑。
- 异常范围收敛到营业总成本的六个组成项。
- 输出每个组成项在“假设仅该字段错误”情况下的候选修正值。

### 3. 单字段残差候选

当无法唯一定位异常字段时，会为合计项和所有参与组成项生成残差修正候选：

- 当前值。
- 若仅修正该字段，使等式成立所需的新值。
- 所需调整金额。

该信息主要用于内部归因，MCP 最简返回不一定完整暴露所有候选值。

### 4. 上层公式反向确认

如果某个下级合计自身校验失败，但该合计作为组成项参与更上层公式且上层公式通过，则 MCP 输出层可以：

- 将下级合计标记为通过，说明其披露值已由上层公式确认。
- 把下级失败下沉到该合计的组成项。

例如利润总额公式使用披露的营业利润能够通过，而营业利润与其明细和不一致时，可确认营业利润披露值本身未发现异常，异常范围转为营业利润组成项。

## 六、现金流量表交叉归因

### 1. 缺失小计向上复用

某个流入或流出小计缺失，但存在子项时：

1. 小计规则标记为失败和字段缺失。
2. 按子项和生成小计推测值。
3. 推测值继续参与对应活动净额校验。

因此可能出现：流入、流出小计因字段缺失而失败，但活动净额使用两个推测小计后校验通过。

### 2. 活动净额确认披露小计

某个小计与其子项和不一致时，如果同时满足：

- 对应活动净额规则校验通过。
- 活动净额使用的是该小计的原始披露值，而非推导值。

则认为：

- 小计披露值已由活动净额交叉确认。
- 差异更可能来自小计的组成项。
- MCP 输出层可将小计显示为通过，并将组成项显示为失败或待复核。

### 3. 子项和反向确认小计错误

某个小计与子项和不一致时，如果把该小计替换成子项重算值后，对应活动净额能够通过，则认为：

- 小计字段本身疑似识别错误。
- 小计的推测值为子项重算值。
- 活动净额使用推测小计重新计算后可标记为通过。

### 4. 上层等式推定缺失项为零

若某条上层公式中：

```text
上层合计 = 已知组成项带符号和
```

且其余组成项缺失，则缺失组成项可以被推定为零。

推定过程可递归向下，例如：

1. 现金及现金等价物净增加额已被经营净额和筹资净额完全解释。
2. 投资活动净额可推定为零。
3. 投资流入、投资流出小计进一步推定为零。

已披露为零但没有子项的小计，也可以由对应活动净额交叉确认后标记为通过。

## 七、MCP 对外输出

勾稽校验首先基于 `view_data` 执行首层规则，并使用 `canonical_data` 完成语义复核和归因。

MCP 对外明细主要包含：

```text
check_item
status
period
suspects
reason
```

常见原因会归一化为以下短提示：

- 校验通过。
- 复核通过。
- 校验未通过。
- 字段缺失。
- 字段缺失，推测值是 `{金额}`。
- 疑似字段错误。
- 疑似字段错误，推测值是 `{金额}`。
- 无法校验。

被动校验失败不会阻断 `map` 主返回；主动校验是否入库由 MCP 服务层根据整体结果处理。

## 八、当前未覆盖范围

### 1. 未校验期末现金余额等式

以下字段已经进入现金流量表映射：

```text
X05000000 现金及现金等价物净增加额
X04010100 期初现金及现金等价物余额
X06010000 期末现金及现金等价物余额
```

但当前没有执行：

```text
期末现金及现金等价物余额
= 期初现金及现金等价物余额
+ 现金及现金等价物净增加额
```

### 2. 未校验现金流量表补充资料

当前没有对“将净利润调节为经营活动现金流量”相关补充资料执行勾稽，因此未覆盖折旧、摊销、资产减值、营运资本变动等间接法项目。

### 3. 未执行跨表校验

当前未覆盖：

- 利润表净利润与现金流量表补充资料净利润的一致性。
- 现金流量表期末现金及现金等价物余额与资产负债表货币资金的一致性或差异调节。
- 现金流相关项目与资产负债表科目变动的交叉验证。

### 4. 未校验比较期

利润表和现金流量表当前只校验最后一期，没有分别校验本期与上期，也没有对期间变动做合理性检查。

### 5. 部分组成项缺失可能误通过

基础公式只汇总实际取得的组成项。只要存在至少一个参与项，就会拿参与项合计与披露合计比较。

因此，当未提取组成项实际非零，但已提取组成项之和恰好等于披露合计时，规则仍可能判定通过。当前只有 canonical 语义变体要求公式中的组成项全部可用。

### 6. 正负号依赖上游映射

利润表中的收益、损失项目按照映射值原始符号参与公式。勾稽层不会根据科目名称自动判断应当取正数还是负数，因此正负号识别错误会直接影响校验结果和失败归因。
